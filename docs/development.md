# 制作・検証記録

## 目的と設計判断

- 自社開発企業に向けて、制作物だけでなく担当範囲・課題・対応・確認を伝える。
- 表示名はHiroto。実際の経験として確認できた内容のみを記載する。
- ENGEIを先頭に置き、チーム開発とAIを活用した既存コードの改修を紹介する。
- Park MapとENGEIのビジュアルには実際の公開サイトのスクリーンショットを使用する。
- logdigはコマンドや処理速度を推測で掲載せず、処理のイメージであることを明記する。
- 軽量な静的サイトとしてAstroで実装し、基本的な表示・移動はJavaScriptに依存させない。
- コンテンツをMarkdownとTypeScriptデータに分離し、作品追加時に一覧と詳細を自動生成する。
- GitHub Pagesのリポジトリ配下への配信を前提に、共通関数で内部URLを生成する。
- 本番公開は後の工程とし、この段階ではローカル実装と公開設定を用意する。

## AIとの役割分担

本人が伝えた情報：制作の背景、チーム人数、使用技術、担当範囲、ENGEIでの具体的な表示不具合と確認内容、資格、AIツールの利用経験。

Codexが補助した作業：情報の整理、紹介文の編集、デザイン・ページ構成、Astroでの実装、実際の公開画面の取得、静的ビルドとブラウザ表示の検証。

## 初回検証（2026-11-21 JST）

- Astroの型チェック：エラー・警告・ヒントなし。
- 本番ビルド：トップ、制作過程、3作品詳細、404の6ページを生成。
- 生成HTML検証：内部ページ・画像・ページ内アンカーを含む113のローカル参照を検証。
- トップページ：ブラウザの幅320 / 390 / 768 / 1440 px相当で横スクロールが発生しないことを確認（スクロールバーを除く実コンテンツ幅は異なる）。
- ENGEI、Park Map、logdig、制作過程：スマートフォン幅で表示と横はみ出しを確認。
- 制作実績リンク、技術一覧へのページ内移動、関連作品リンク、トップに戻るリンクを操作。
- 技術アイコンの読み込みを確認。
- キーボードのTabで本文スキップリンクにフォーカスし、Enterで本文へ移動することを確認。
- 存在しないURLで独自404ページが表示され、トップページへ戻れることを確認。

ブラウザ確認はデスクトップブラウザの表示幅を変更して実施。実機のiOS Safari・Android Chromeでの検証や、GitHub Pages上での最終確認は未実施です。外部リンクは公開先を示すもので、相手サイトの継続稼働は保証しません。
